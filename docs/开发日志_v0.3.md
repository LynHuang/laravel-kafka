### 关键设计点

#### 1. `pollBatch` 实现要点

```php
public function pollBatch(int $max, int $timeoutMs = 1000): array
```

**死循环防护（4 重保险）**：
1. 拉够 `$max` 条 → `break`
2. 达到 `deadline`（$start + $timeoutMs/1000） → `break`
3. **连续 2 次** `RD_KAFKA_RESP_ERR__TIMED_OUT`（broker 立即说无消息） → 早返回
4. 达到 `maxIters = $max + 2`（极端情况防御） → `break`

**为什么"连续 2 次 TIMED_OUT 退出"**：
- librdkafka `consume(0)` 会**立即**返回 TIMED_OUT（broker 无消息时）
- 如果只用 deadline 检查，mock 测试环境下（consume 不阻塞）会**死循环**
- 生产环境：librdkafka 真实阻塞到 timeoutMs，第二次 consume 阻塞到 deadline 才返回 → 自然退出
- "连续 2 次" 保护 broker 稀疏消息场景：业务方想"批量"是"1s 内尽可能多拉"，不是"硬等满 1s"

**TIMED_OUT 早返回**：
- 拉到至少 1 条 + 遇到 TIMED_OUT → 立即返回（不空等到 deadline）
- 让业务方更早进入 handler 处理循环

**循环结构**：用 `for ($i = 0; $i < $maxIters; $i++)` 而非 `while`，配合 `$maxIters` 上限防御死循环。

#### 2. `commitBatch` 实现

```php
public function commitBatch(): void
{
    $this->commitAsync();
}
```

**librdkafka 没有"按消息列表 commit" API**——它的 commit 是"消费位置"，调一次 `commitAsync` 就 commit 当前位置及之前所有未提交的 offset。

**整批原子语义**：
- 业务方在 batch 处理**全部成功**后调 `commitBatch()`
- 单条失败 → **不**调 `commitBatch()` → 整批下次重投
- v0.3 简化：**不支持**部分 commit（要么全成功要么全失败重投）

#### 3. `kafka:work` 集成

```bash
php artisan kafka:work --queue=emails,orders \
    --batch-size=50 \
    --batch-timeout=2000
```

**主循环分支**：
- `--batch-size=1`（默认）→ 走 v0.1/v0.2 单条行为（`poll` + `processMessage`）
- `--batch-size>1` → 走 v0.3 批量行为（`pollBatch` + 整批处理 + 整批 commit）

**单条失败处理**（批量模式）：
```php
foreach ($messages as $message) {
    try {
        $this->processMessage($resolver, $consumer, $message);
    } catch (\Throwable $e) {
        $this->error('[kafka:work] batch message failed: ... — not committing batch');
        $batchSuccess = false;
        break;
    }
}
if ($batchSuccess) {
    $consumer->commitBatch();
}
```

注意：单条失败 → `break` 不调 `commitBatch` → 整批下次重投 → 失败的那条也会重试。**这可能导致同一失败消息被无限重试**（毒消息问题），v0.4 评估引入"毒消息 dead-letter on N failures"机制。

### 与 mateusjunges 的差异

| 特性 | mateusjunges | 我们（v0.3） |
| --- | --- | --- |
| 批量 API | 无 `pollBatch`（手动 `consume` 循环） | `Consumer::pollBatch` 封装（死循环防护 + 早返回） |
| 整批 commit | 手动 `commitAsync` | `Consumer::commitBatch` 包装 + 命名 |
| `--batch-size` CLI | 无 | `kafka:work --batch-size` |

### 已知待办（v0.4 评估）

- **毒消息问题**：单条失败 → 整批重投 → 同一毒消息被无限重试。v0.4 评估"连续 N 次失败 → dead-letter"机制
- **batch_size 与 max-time 协同**：当前主循环是"先 max-time 退出 vs 先 max-jobs 退出"。批量模式下 `max-jobs` 应该按"消息数"还是"批次数"算？当前按消息数（`$jobCount += count($messages)`）
- **per-partition 批量**：当前 `pollBatch` 不分 partition，混在一起。某些场景（同 partition 严格顺序）需要 per-partition 批量 → v0.4 评估
