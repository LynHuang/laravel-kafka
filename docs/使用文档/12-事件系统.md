# 12 事件系统

`laravel-kafka` 在消息生命周期的关键节点 dispatch Laravel 事件，业务方订阅后可以做日志、审计、监控、动态控制等。

---

## 1. 6 个事件

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `MessagePublishing` | `KafkaQueue::pushRaw` 调 `Producer::send` **之前** | `$topic`, `$message` |
| `MessagePublished` | `Producer::send` 同步成功 **之后** | `$topic`, `$message` |
| `MessageConsuming` | `Consumer::poll` 拿到消息 **之后**，handler 调之前 | `$topic`, `$message` |
| `MessageConsumed` | handler 返回 `ACK` / `REQUEUE` 之后 | `$topic`, `$message`, `$action` |
| `MessageFailed` | handler 抛异常 / 返回 `DLQ` 后 | `$topic`, `$message`, `$error` |
| `MessageSentToDLQ` | `FailedHandler` 把消息写入 DLQ topic 后 | `$topic`, `$message`, `$dlqTopic`, `$error` |

所有事件都在 `LaravelKafka\Events\` 命名空间下。

## 2. 订阅方式

### 方式 A：EventServiceProvider

```php
// app/Providers/EventServiceProvider.php
namespace App\Providers;

use Illuminate\Foundation\Support\Providers\EventServiceProvider;
use LaravelKafka\Events\MessagePublishing;
use LaravelKafka\Events\MessagePublished;
use LaravelKafka\Events\MessageConsuming;
use LaravelKafka\Events\MessageConsumed;
use LaravelKafka\Events\MessageFailed;
use LaravelKafka\Events\MessageSentToDLQ;

class EventServiceProvider extends EventServiceProvider
{
    protected $listen = [
        MessagePublishing::class => [
            \App\Listeners\LogPublishing::class,
        ],
        MessagePublished::class => [
            \App\Listeners\IncrementMetrics::class,
        ],
        MessageConsuming::class => [
            \App\Listeners\TraceContextInject::class,
        ],
        MessageConsumed::class => [
            \App\Listeners\RecordLatency::class,
        ],
        MessageFailed::class => [
            \App\Listeners\AlertOps::class,
        ],
        MessageSentToDLQ::class => [
            \App\Listeners\ArchiveDLQ::class,
        ],
    ];
}
```

### 方式 B：闭包订阅（动态）

```php
// app/Providers/AppServiceProvider.php
public function boot(): void
{
    \Event::listen(MessagePublished::class, function (MessagePublished $event) {
        \Log::info('Kafka message published', [
            'topic'   => $event->topic,
            'key'     => $event->message->key(),
            'payload' => substr($event->message->payload(), 0, 100),
        ]);
    });
}
```

### 方式 C：Observer

业务方有复杂订阅逻辑时，写个 Observer：

```php
namespace App\Observers;

use LaravelKafka\Events\MessagePublished;

class KafkaMessageObserver
{
    public function handlePublished(MessagePublished $event): void
    {
        \Log::info('Published', [
            'topic' => $event->topic,
            'key'   => $event->message->key(),
        ]);
    }

    public function handleFailed(MessageFailed $event): void
    {
        \Log::error('Failed', [
            'topic' => $event->topic,
            'error' => $event->error->getMessage(),
        ]);
    }
}
```

注册：

```php
// app/Providers/EventServiceProvider.php
public function boot(): void
{
    \Event::listen(MessagePublished::class, [KafkaMessageObserver::class, 'handlePublished']);
    \Event::listen(MessageFailed::class, [KafkaMessageObserver::class, 'handleFailed']);
}
```

## 3. 各事件详解

### 3.1 `MessagePublishing`

**触发**：`KafkaQueue::pushRaw` 即将调 `Producer::send` 之前

**用途**：

- 业务方在发送前**修改**消息（如追加业务 header）
- 审计 / 限流（高频发送时拒绝）
- 性能采样

```php
\Event::listen(MessagePublishing::class, function (MessagePublishing $event) {
    // 例子：每条消息都打 `x-biz-source` header
    $event->message;  // 当前 Message 对象
    $event->topic;    // 物理 topic
    // 注：v0.4.1 当前 message 是只读，业务方想改 message 需在 Queue 层做
});
```

### 3.2 `MessagePublished`

**触发**：`Producer::send` 同步成功（broker ack）

**用途**：

- 业务 metrics（成功数 / 延迟）
- 发送成功埋点

```php
\Event::listen(MessagePublished::class, function (MessagePublished $event) {
    \Metrics::increment('kafka.produced', [
        'topic' => $event->topic,
    ]);
});
```

### 3.3 `MessageConsuming`

**触发**：`Consumer::poll` 拿到消息，handler 调之前

**用途**：

- 注入 trace context（业务方跨服务调用）
- 记录消费开始时间（算延迟）

```php
\Event::listen(MessageConsuming::class, function (MessageConsuming $event) {
    $traceparent = $event->message->header('traceparent');
    if ($traceparent) {
        // 设置当前请求的 trace context
        \App\Support\TraceContext::set($traceparent);
    }
});
```

### 3.4 `MessageConsumed`

**触发**：handler 返回 `ACK` / `REQUEUE` 后

**用途**：

- 记录消费成功 / 失败 / 重试
- 算 end-to-end 延迟（`x-enqueued-at` → 现在）

```php
\Event::listen(MessageConsumed::class, function (MessageConsumed $event) {
    $enqueuedAt = (int) $event->message->header('x-enqueued-at', '0');
    $now = (int) (microtime(true) * 1000);
    $latencyMs = $enqueuedAt > 0 ? $now - $enqueuedAt : 0;

    \Metrics::histogram('kafka.consume.latency', $latencyMs, [
        'topic' => $event->topic,
        'action' => $event->action,
    ]);
});
```

### 3.5 `MessageFailed`

**触发**：handler 抛异常 或 返回 `DLQ`

**用途**：

- 立即告警（钉钉 / 企微 / 邮件）
- 上报 Sentry
- 业务方自定义的 retry 策略

```php
\Event::listen(MessageFailed::class, function (MessageFailed $event) {
    \Sentry\captureException($event->error);
    \Log::error('Kafka consume failed', [
        'topic' => $event->topic,
        'key'   => $event->message->key(),
        'error' => $event->error->getMessage(),
    ]);
});
```

### 3.6 `MessageSentToDLQ`

**触发**：`DlqFailedJobHandler` 写入 DLQ topic 成功之后

**用途**：

- 长期归档（DLQ 写到 S3 / OSS）
- 触发修复工单

```php
\Event::listen(MessageSentToDLQ::class, function (MessageSentToDLQ $event) {
    // 写 S3 备份
    \Storage::disk('s3')->put(
        "dlq/{$event->dlqTopic}/" . now()->format('Ymd') . "/{$event->message->key()}.json",
        json_encode([
            'original_topic' => $event->topic,
            'dlq_topic' => $event->dlqTopic,
            'payload' => $event->message->payload(),
            'headers' => $event->message->headers(),
            'error' => $event->error->getMessage(),
        ], JSON_PRETTY_PRINT)
    );
});
```

## 4. 事件触发流程图

```
┌──────────────────────────────────────────────────────────┐
│                       push 流程                          │
│                                                          │
│  Queue::push($job)                                      │
│      │                                                   │
│      ▼                                                   │
│  KafkaQueue::pushRaw                                    │
│      │                                                   │
│      ├─► dispatch(MessagePublishing) ◄─── 监听者 A        │
│      │                                                   │
│      ▼                                                   │
│  Producer::send                                          │
│      │                                                   │
│      ├─► dispatch(MessagePublished)  ◄─── 监听者 B        │
│      ▼                                                   │
│  ✓ 入队成功                                              │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│                       consume 流程                       │
│                                                          │
│  Consumer::poll                                          │
│      │                                                   │
│      ▼                                                   │
│  NativeHandler::handle                                   │
│      │                                                   │
│      ├─► dispatch(MessageConsuming)  ◄─── 监听者 C        │
│      │                                                   │
│      ▼                                                   │
│  $job->handle()                                          │
│      │                                                   │
│      ├── 成功 ──► dispatch(MessageConsumed) ◄─── 监听者 D │
│      │                                                   │
│      ├── 异常 ──► dispatch(MessageFailed)    ◄─── 监听者 E│
│      │             │                                     │
│      │             └─► FailedHandler::handle             │
│      │                     │                             │
│      │                     ├── 写 database                │
│      │                     └── 写 DLQ topic                │
│      │                            │                      │
│      │                            ▼                      │
│      │                    dispatch(MessageSentToDLQ) ◄───F│
│      │                                                   │
│      └── requeue (attempt+1)                             │
└──────────────────────────────────────────────────────────┘
```

## 5. 失败处理 vs 事件

`MessageFailed` 事件在 handler 抛异常时触发。**注意**：

- `hybrid` 模式下，**重试中**（`attempt < max_attempts`）也会触发 `MessageFailed`
- 业务方想区分"重试中"和"最终失败"，看 `x-attempt` header：

```php
\Event::listen(MessageFailed::class, function (MessageFailed $event) {
    $attempt = (int) $event->message->header('x-attempt', '0');
    $maxAttempts = (int) config('kafka.connections.default.failed.hybrid.max_attempts', 3);

    if ($attempt >= $maxAttempts) {
        // 最终失败 → 告警
        \Alert::send("Kafka job 最终失败: {$event->topic}");
    }
    // 重试中 → 不告警（避免噪声）
});
```

## 6. 实战示例：可观测性三件套

### 日志：结构化记录 publish / consume

```php
namespace App\Listeners;

use LaravelKafka\Events\MessagePublished;
use LaravelKafka\Events\MessageConsumed;

class KafkaMetrics
{
    public function onPublished(MessagePublished $event): void
    {
        \Log::channel('kafka')->info('kafka.published', [
            'topic' => $event->topic,
            'key'   => $event->message->key(),
            'bytes' => strlen($event->message->payload()),
        ]);
    }

    public function onConsumed(MessageConsumed $event): void
    {
        $enqueuedAt = (int) $event->message->header('x-enqueued-at', '0');
        $now = (int) (microtime(true) * 1000);
        $latencyMs = $enqueuedAt > 0 ? $now - $enqueuedAt : 0;

        \Log::channel('kafka')->info('kafka.consumed', [
            'topic'       => $event->topic,
            'action'      => $event->action,
            'latency_ms'  => $latencyMs,
            'attempts'    => (int) $event->message->header('x-attempt', '0'),
        ]);
    }
}
```

注册：

```php
\Event::listen(MessagePublished::class, [KafkaMetrics::class, 'onPublished']);
\Event::listen(MessageConsumed::class, [KafkaMetrics::class, 'onConsumed']);
```

### 监控：Prometheus metrics

```php
namespace App\Listeners;

use LaravelKafka\Events\MessagePublished;
use LaravelKafka\Events\MessageFailed;
use Prometheus\Counter;

class KafkaPrometheus
{
    public function onPublished(MessagePublished $event): void
    {
        Counter::getOrRegister('kafka_messages_produced_total', 'Total produced', ['topic'])
            ->inc([$event->topic]);
    }

    public function onFailed(MessageFailed $event): void
    {
        Counter::getOrRegister('kafka_messages_failed_total', 'Total failed', ['topic', 'exception'])
            ->inc([$event->topic, get_class($event->error)]);
    }
}
```

### 告警：钉钉 / 企微

```php
\Event::listen(MessageSentToDLQ::class, function (MessageSentToDLQ $event) {
    $message = sprintf(
        "[Kafka DLQ] Topic: %s\nDLQ: %s\nError: %s\nKey: %s",
        $event->topic,
        $event->dlqTopic,
        $event->error->getMessage(),
        $event->message->key() ?? '(null)',
    );

    \Http::post(env('DINGTALK_WEBHOOK'), [
        'msgtype' => 'text',
        'text'    => ['content' => $message],
    ]);
});
```

## 7. 事件 vs Laravel Queue 事件

Laravel `Illuminate\Queue\Events\JobFailed` 也由 `LaravelKafkaServiceProvider` 监听，但**不**自动 dispatch `MessageFailed`（避免重复）。业务方可以二选一：

| 想监听 | 订阅 |
| --- | --- |
| 仅本包 Kafka 失败 | `LaravelKafka\Events\MessageFailed` |
| Laravel Queue 全栈（不限于 Kafka） | `Illuminate\Queue\Events\JobFailed` |

> Kafka 失败是 Laravel Queue 失败的子集，但**信息更丰富**（含 `$message` 值对象）。

---

## 8. 性能影响

事件 dispatch 是 Laravel 标准做法，**几乎零开销**：

- 无订阅者 → 1 次 `is_array($listeners)` 检查
- 有订阅者 → 同步执行 → 1 次方法调用

业务方监听器里**避免**做重操作（如 HTTP 调用 / 慢 DB 查询），否则会拖慢 Kafka producer / consumer。

> 需要重操作的监听器用 Laravel Queue 异步事件：业务方订阅 Laravel 内置的 `QueueableListener` 模式。
