# 06 延迟消息

`laravel-kafka` 用**时间轮分层 topic** 实现延迟消息 —— 不依赖 broker 端定时器，所有延迟消息都持久化在 Kafka。

---

## 1. 概念

Kafka 不原生支持延迟消息。本实现用"分层 topic + 过期 requeue"模拟时间轮：

```
Queue::later(3,    $job)  →  写 "delay-5s"   topic
Queue::later(15,   $job)  →  写 "delay-30s"  topic
Queue::later(45,   $job)  →  写 "delay-60s"  topic
Queue::later(400,  $job)  →  写 "delay-1800s" topic
                       ... 1 天兜底
```

`tiers = [5, 30, 60, 300, 1800, 3600, 86400]`（秒）7 层。

`kafka:delay:work` worker **尚未发布**（路线图 v0.6）监听所有 tier topic：
- 拉一条延迟消息
- 检查 `x-available-at` header（到期时间）
- 到期 → requeue 回主 topic（`x-attempt: 0`）
- 未到期 → 暂存（v0.6 实现内存延迟队列；**当前 v0.5.2 需业务方按 tier 单独监听**）

> **v0.5.2 修正**：`kafka:delay:work` 命令从未发布（`src/Console/` 只有 4 个命令）。`Queue::later()`
> 只写 tier topic + `x-available-at`/`x-original-queue` header，**消费侧需业务方自己监听 tier topic**。

### 路由规则（v0.1 §4.5 方案 A）

给定 `delay` 选**最近一层**（向上取整）：

| 实际 delay | 选 tier | 写到 topic |
| --- | --- | --- |
| 3s | 5s | `delay-5s` |
| 10s | 30s | `delay-30s` |
| 45s | 60s | `delay-60s` |
| 400s | 1800s | `delay-1800s` |
| 90000s (1 天+) | 86400s | `delay-86400s` |

最大延迟 = 86400s = 1 天。需要更长延迟？调整 `tiers` 配置。

---

## 2. 配置

```php
// config/kafka.php
'connections' => [
    'default' => [
        'delay' => [
            'strategy'     => 'time_wheel',
            'tiers'        => [5, 30, 60, 300, 1800, 3600, 86400],
            'topic_prefix' => 'delay',  // 生成 "delay-5s" 等
        ],
    ],
],
```

> 业务方调 `Queue::later($delay, $job)` 时**不传** topic 名字，框架按 `tiers` 自动选。

---

## 3. 使用

### 标准 Laravel `Queue::later` API

```php
// 3 秒后执行
Queue::later(3, new SendReminderEmail($userId));

// 5 分钟后执行
Queue::later(300, new ExpireOrder($orderId));

// 1 天后执行
Queue::later(86400, new DailyReportJob());
```

### `dispatch` 链式

```php
use App\Jobs\SendReminderEmail;

SendReminderEmail::dispatch($userId)->delay(now()->addSeconds(30));
```

### 自定义队列（key 路由）

```php
Queue::later(60, $job, '', 'reminder-queue', 'user-42');
```

## 4. `DelayRouter` 低层 API

业务方已有延迟逻辑想自己路由时：

```php
use LaravelKafka\Delay\DelayRouter;

$router = new DelayRouter(
    tiers: [5, 30, 60, 300, 1800, 3600, 86400],
    topicPrefix: 'delay',
);

$route = $router->route(45);
// ['topic' => 'delay-60s', 'tier' => 60]

$topics = $router->allTopics();
// ['delay-5s', 'delay-30s', 'delay-60s', 'delay-300s', 'delay-1800s', 'delay-3600s', 'delay-86400s']

$tier = $router->parseTier('delay-5s');  // 5
```

### `DelayRouter` API 完整列表

| 方法 | 说明 |
| --- | --- |
| `__construct(array $tiers, string $topicPrefix = 'delay')` | 构造（tiers 必须升序 + 全 > 0） |
| `route(int $delaySeconds): array` | 给定延迟秒数，返回 `['topic' => '...', 'tier' => ...]` |
| `allTopics(): array` | 所有 tier topic 列表 |
| `tiers(): array` | tier 秒数列表（升序） |
| `parseTier(string $topic): int` | 从 topic 名反向解析 tier 秒数（找不到返回 0） |

### 校验规则

构造时校验 tiers：
- 必须升序（`sort($sorted) === $tiers`）
- 全部 > 0
- 失败抛 `LaravelKafka\Exceptions\KafkaException`

## 5. `kafka:delay:work`（路线图 v0.6，尚未发布）

> **v0.5.2 当前未发布此命令**（`src/Console/` 无 delay:work），业务方需自己起 worker 监听 tier topic。

未来发布时用法：

```bash
php artisan kafka:delay:work \
    --connection=default \
    --max-time=3600 \
    --sleep=1
```

行为：
- 订阅所有 tier topic（`delay-5s, delay-30s, ...`）
- 每条消息检查 `x-available-at` header
- 到期 → requeue 回 `x-original-queue`（主 topic）并重置 `x-attempt: 0`
- 未到期 → 暂存到内存延迟队列（轮询检查）

## 6. 当前 v0.5.2 临时方案

业务方需要延迟消息功能时，**两个选择**：

### 选项 A：自己起 tier worker（手动实现）

```php
// 监听 delay-5s
// v0.5.2 修正: Kafka::connection() 返回 KafkaQueue (没有 kafka() 方法).
// 要用低层 Consumer, 用 ConsumerFactory:
$consumer = app(\LaravelKafka\Consumer\ConsumerFactory::class)
    ->make(Kafka::config('default'), new \LaravelKafka\Consumer\Subscription(['delay-5s']));
$rdConsumer = $consumer->kafka();  // 拿底层 RdKafka\KafkaConsumer
$rdConsumer->subscribe(['delay-5s']);

while (true) {
    $msg = $rdConsumer->consume(1000);
    if ($msg === null) continue;
    
    $availableAt = (int) ($msg->headers['x-available-at'] ?? 0);
    $now = (int) (microtime(true) * 1000);
    
    if ($now < $availableAt) {
        // 还没到期 — 重新放回（简单实现，业务方按需优化）
        sleep(($availableAt - $now) / 1000);
    }
    
    // 到期 → requeue 回主 topic
    Kafka::connection()->pushRaw(
        $msg->payload,
        $msg->headers['x-original-queue'] ?? 'laravel-jobs',
        ['key' => $msg->key],
    );
    
    $consumer->commit($msg);
}
```

### 选项 B：用第三方调度器（Redis / DB polling）

把延迟消息存到 Redis ZSET（score = 到期时间戳），单独起 cron worker 每秒 poll：
- 到期 → `Kafka::connection()->pushRaw(...)` 写 Kafka
- 实现简单，但需要 Redis 持久化

> **生产推荐**：等 v0.6 正式 `kafka:delay:work` 发布后用选项 A 的官方版本。

## 7. 限制与权衡

### 优点

- **Broker 持久化**：worker 重启 / broker 切换不丢延迟消息
- **简单可靠**：7 个固定 topic，broker 端配置简单
- **水平扩展**：多个 `kafka:delay:work` worker 自动 partition 互斥

### 缺点

- **延迟精度 = tier 间隔**：3s 延迟实际等 5s 才被消费
- **topic 数量固定**：7 个 tier 对应 7 个 topic
- **冷消息积压**：高频小延迟消息会集中在 5s tier topic

### 调整 tiers

```php
'delay' => [
    // 高频小延迟：精细粒度
    'tiers' => [1, 5, 30, 60, 300, 1800, 3600, 21600, 86400],

    // 低频大延迟：粗粒度
    'tiers' => [60, 300, 1800, 3600, 86400],
],
```

调整后必须保证 tier 升序。

## 8. 完整示例：订单超时取消

```php
namespace App\Jobs;

use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;

class CancelUnpaidOrder implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function __construct(public int $orderId) {}

    public function handle(): void
    {
        $order = \DB::table('orders')->find($this->orderId);
        if ($order && $order->status === 'pending') {
            \DB::table('orders')
                ->where('id', $this->orderId)
                ->update(['status' => 'cancelled']);
            \Log::info("Order {$this->orderId} auto-cancelled after 30 minutes");
        }
    }
}
```

dispatch：

```php
// 下单后 30 分钟未支付 → 自动取消
CancelUnpaidOrder::dispatch($orderId)->delay(now()->addMinutes(30));
```

或显式：

```php
Queue::later(1800, new CancelUnpaidOrder($orderId));
```

消息会写到 `delay-1800s` topic，30 分钟后由 `kafka:delay:work` worker（v0.6 计划，尚未发布）requeue 回 `laravel-jobs` 主 topic，`kafka:work` 消费执行 `handle()`。**当前 v0.5.2 需业务方自己监听 tier topic**（见 §6）。
