# 14 安全连接

4 种协议（PLAINTEXT / SSL / SASL_PLAINTEXT / SASL_SSL）+ 证书配置 + SASL 机制。

---

## 1. 4 种协议对比

| 协议 | 加密 | 认证 | 适用 |
| --- | --- | --- | --- |
| `PLAINTEXT` | ❌ | ❌ | 本地开发 / 内网裸跑 |
| `SSL` | ✅（TLS） | ❌（单向 TLS，可选双向 mTLS） | 公网但无身份认证 |
| `SASL_PLAINTEXT` | ❌ | ✅ SASL | 内网但有 Kerberos / 账号密码 |
| `SASL_SSL` | ✅ | ✅ | **公网 + 账号密码**（生产推荐） |

---

## 2. PLAINTEXT（默认）

```php
'connections' => [
    'default' => [
        'protocol' => 'PLAINTEXT',
        'brokers'  => 'localhost:9092',
    ],
],
```

> 本地开发 / Docker / 内网裸跑。**生产环境禁用**（明文传输数据 + 无认证）。

## 3. SSL（单向 TLS）

业务方只想要加密，不想要身份认证：

```php
'connections' => [
    'default' => [
        'protocol' => 'SSL',
        'brokers'  => 'kafka-prod:9093',
        'ssl' => [
            'ca_location' => '/etc/ssl/kafka-ca.pem',  // broker CA 证书（验证 broker）
            // 可选：双向 mTLS
            'cert_location' => '/etc/ssl/client.crt',   // 客户端证书
            'key_location'  => '/etc/ssl/client.key',   // 客户端私钥
            'key_password'  => env('KAFKA_SSL_KEY_PASSWORD'),
        ],
    ],
],
```

`.env`：

```dotenv
KAFKA_PROTOCOL=SSL
KAFKA_SSL_CA=/etc/ssl/kafka-ca.pem
KAFKA_SSL_CERT=/etc/ssl/client.crt
KAFKA_SSL_KEY=/etc/ssl/client.key
```

### 配置说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `ca_location` | ✅ | Broker CA 证书路径（librdkafka 用来验证 broker 身份） |
| `cert_location` | ❌（mTLS 才需要） | 客户端证书（broker 验证 client 身份） |
| `key_location` | ❌（mTLS 才需要） | 客户端私钥 |
| `key_password` | ❌ | 私钥密码（如果私钥加密了） |

### 自签证书

业务方用 `openssl` 生成测试证书：

```bash
# 生成 CA
openssl genrsa -out ca.key 2048
openssl req -new -x509 -key ca.key -out ca.crt -days 365 -subj "/CN=KafkaCA"

# 生成服务端证书
openssl genrsa -out server.key 2048
openssl req -new -key server.key -out server.csr -subj "/CN=kafka-broker"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365

# 信任链：把 CA 加到系统信任（broker 端）
sudo cp ca.crt /usr/local/share/ca-certificates/kafka-ca.crt
sudo update-ca-certificates
```

### broker 端 SSL 配置

业务方用 `confluentinc/cp-kafka` Docker 时加环境变量：

```bash
docker run -d --name kafka-ssl \
    -p 9093:9093 \
    -e KAFKA_LISTENERS=SSL://0.0.0.0:9093 \
    -e KAFKA_ADVERTISED_LISTENERS=SSL://localhost:9093 \
    -e KAFKA_SSL_KEYSTORE_LOCATION=/etc/kafka/secrets/server.keystore.jks \
    -e KAFKA_SSL_KEYSTORE_PASSWORD=<password> \
    -e KAFKA_SSL_TRUSTSTORE_LOCATION=/etc/kafka/secrets/server.truststore.jks \
    -e KAFKA_SSL_TRUSTSTORE_PASSWORD=<password> \
    -v /path/to/certs:/etc/kafka/secrets \
    confluentinc/cp-kafka:7.5.0
```

## 4. SASL_PLAINTEXT

业务方有 Kerberos / 账号密码认证，但**网络是内网**：

```php
'connections' => [
    'default' => [
        'protocol' => 'SASL_PLAINTEXT',
        'brokers'  => 'kafka-prod:9092',
        'sasl' => [
            'mechanism' => 'SCRAM-SHA-512',  // PLAIN | SCRAM-SHA-256 | SCRAM-SHA-512
            'username'  => env('KAFKA_SASL_USERNAME'),
            'password'  => env('KAFKA_SASL_PASSWORD'),
        ],
    ],
],
```

### SASL 机制

| 机制 | 安全 | 性能 | 适用 |
| --- | --- | --- | --- |
| `PLAIN` | ❌ 密码明文 | 🚀 最快 | **仅测试**，内网 + 临时使用 |
| `SCRAM-SHA-256` | ✅ | 中 | 一般 |
| `SCRAM-SHA-512` | ✅✅ | 慢 10% | **生产推荐** |

> `PLAIN` 在 `SASL_PLAINTEXT` 下明文传密码 —— **不要用于生产**。`SCRAM-*` 机制密码以 challenge-response 形式传输，broker 不存明文。

### broker 端 SASL 配置

Kafka server config：

```properties
# config/kafka/server.properties
listeners=SASL_PLAINTEXT://0.0.0.0:9092
advertised.listeners=SASL_PLAINTEXT://kafka-prod:9092
security.inter.broker.protocol=SASL_PLAINTEXT
sasl.mechanism.inter.broker.protocol=SCRAM-SHA-512
sasl.enabled.mechanisms=SCRAM-SHA-512

# 创建 SCRAM 凭据
# kafka-configs.sh --zookeeper localhost:2181 --alter --add-config 'SCRAM-SHA-512=[password=secret]' --entity-type users --entity-name alice
```

## 5. SASL_SSL（生产推荐）

加密 + 身份认证：

```php
'connections' => [
    'default' => [
        'protocol' => 'SASL_SSL',
        'brokers'  => 'kafka-prod:9094',
        'sasl' => [
            'mechanism' => 'SCRAM-SHA-512',
            'username'  => env('KAFKA_SASL_USERNAME'),
            'password'  => env('KAFKA_SASL_PASSWORD'),
        ],
        'ssl' => [
            'ca_location' => '/etc/ssl/kafka-ca.pem',
        ],
    ],
],
```

`.env`：

```dotenv
KAFKA_PROTOCOL=SASL_SSL
KAFKA_BROKERS=kafka-prod:9094

KAFKA_SASL_MECHANISM=SCRAM-SHA-512
KAFKA_SASL_USERNAME=app-producer
KAFKA_SASL_PASSWORD=<secret>

KAFKA_SSL_CA=/etc/ssl/kafka-ca.pem
```

### broker 端配置

```properties
# config/kafka/server.properties
listeners=SASL_SSL://0.0.0.0:9094
advertised.listeners=SASL_SSL://kafka-prod:9094
security.inter.broker.protocol=SASL_SSL
sasl.mechanism.inter.broker.protocol=SCRAM-SHA-512
sasl.enabled.mechanisms=SCRAM-SHA-512

ssl.keystore.location=/etc/kafka/secrets/server.keystore.jks
ssl.keystore.password=<keystore-password>
ssl.key.password=<key-password>
ssl.truststore.location=/etc/kafka/secrets/server.truststore.jks
ssl.truststore.password=<truststore-password>
ssl.client.auth=required  # 可选：要求客户端证书（mTLS）
```

## 6. 故障排查

### SSL 握手失败

```
Error: SSL handshake failed: certificate verify failed
```

**可能原因**：

1. CA 证书路径错（`ca_location` 找不到）
2. CA 证书过期
3. Broker 证书 CN 与实际 hostname 不符

**诊断**：

```bash
# 用 openssl 验证 broker 证书
openssl s_client -connect kafka-prod:9094 -showcerts < /dev/null

# 业务方客户端的 librdkafka 启用 debug
# 临时在 .env 加:
KAFKA_DEBUG=ssl,broker
```

### SASL 认证失败

```
Error: SASL authentication failed: Invalid credentials
```

**可能原因**：

1. 用户名 / 密码错
2. 用户在 broker 没创建（kafka-configs.sh 没跑）
3. 机制不匹配（broker 不支持 SCRAM-SHA-512，但客户端配了）

**诊断**：

```bash
# 用 kafkacat 验证 SASL
kafkacat -b kafka-prod:9094 -X sasl.mechanism=SCRAM-SHA-512 \
    -X sasl.username=app-producer -X sasl.password=<secret> \
    -X security.protocol=SASL_SSL -L
```

### 连接超时

```
Error: Connection timed out after 30000 ms
```

**可能原因**：

1. 防火墙挡住端口
2. broker 监听端口错（9094 vs 9093）
3. `KAFKA_BROKERS` 写错

**诊断**：

```bash
# 测试网络可达
telnet kafka-prod 9094

# 用 kcat 测连通
kcat -b kafka-prod:9094 -L
```

## 7. 完整示例：AWS MSK

业务方用 AWS Managed Streaming for Apache Kafka：

```php
'connections' => [
    'msk' => [
        'protocol' => 'SASL_SSL',
        'brokers'  => 'b-1.msk-cluster.kafka.us-east-1.amazonaws.com:9094,b-2.msk-cluster.kafka.us-east-1.amazonaws.com:9094',
        'client_id' => 'laravel-kafka-msk',
        'sasl' => [
            'mechanism' => 'SCRAM-SHA-512',
            'username'  => env('MSK_SASL_USERNAME'),
            'password'  => env('MSK_SASL_PASSWORD'),
        ],
        'ssl' => [
            'ca_location' => '/etc/ssl/aws-msk-bundle.crt',  // AWS 信任 CA bundle
        ],
    ],
],
```

业务方：

```php
Kafka::connection('msk')->push(new ProcessOrder($id));
```

## 8. 完整示例：Confluent Cloud

```php
'connections' => [
    'confluent' => [
        'protocol' => 'SASL_SSL',
        'brokers'  => 'pkc-xxxxx.us-east-1.aws.confluent.cloud:9092',
        'client_id' => 'laravel-kafka-confluent',
        'sasl' => [
            'mechanism' => 'PLAIN',  // Confluent Cloud 用 PLAIN（密码 API key）
            'username'  => env('CONFLUENT_API_KEY'),
            'password'  => env('CONFLUENT_API_SECRET'),
        ],
    ],
],
```

> Confluent Cloud 的 SASL **必须**用 PLAIN（API key 本身就是 secret）。Wire 协议是 SASL_SSL，所以**仍然加密**。

## 9. 多连接混合

```php
'connections' => [
    'local' => [
        'protocol' => 'PLAINTEXT',
        'brokers'  => 'localhost:9092',
    ],
    'production' => [
        'protocol' => 'SASL_SSL',
        'brokers'  => 'kafka-prod:9094',
        'sasl' => [
            'mechanism' => 'SCRAM-SHA-512',
            'username'  => env('PROD_KAFKA_USER'),
            'password'  => env('PROD_KAFKA_PASS'),
        ],
        'ssl' => [
            'ca_location' => env('PROD_KAFKA_CA'),
        ],
    ],
],
```

业务方按需：

```php
// 本地开发
Kafka::connection('local')->push(new MyJob());

// 生产
Kafka::connection('production')->push(new MyJob());
```
