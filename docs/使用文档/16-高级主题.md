## 1. Octane 兼容

Laravel Octane（用 Swoole / RoadRunner 跑长进程）下，Kafka 客户端需要：

1. **每请求结束释放 fd**（避免 fd 泄漏，最终耗尽系统资源）
2. **共享 librdkafka 实例**（避免每请求重新建连接，浪费资源）

### 最佳实践：每请求结束 `disconnect()`

```php
namespace App\Http\Middleware;

use Closure;
use LaravelKafka\Manager\KafkaManager;

class ReleaseKafkaConnections
{
    public function __construct(private KafkaManager $manager) {}

    public function handle($request, Closure $next)
    {
        $response = $next($request);

        // 每请求结束释放所有 connection
        $this->manager->disconnect();           // 默认 connection
        $this->manager->disconnect('reports');  // 多 connection

        return $response;
    }
}
```

注册：

```php
// app/Http/Kernel.php
protected $middleware = [
    // ...
    \App\Http\Middleware\ReleaseKafkaConnections::class,
];
```

### Octane 启动时 warm-up

```php
// app/Providers/AppServiceProvider.php
public function boot(): void
{
    if (\PHP_SAPI === 'cli-server' || app()->bound('octane')) {
        // Warm up KafkaManager（绑定单例）
        app('kafka.manager')->registerConnections(config('kafka.connections'));
    }
}
```

### 注意事项

- **不要**在 `register()` 阶段触发 `connection()`（会建 librdkafka 实例）
- **不要**在 `disconnect()` 后再调用 connection（重新建连接，开销大）—— 只在请求**结束**时调
- Swoole / RoadRunner Worker 进程**不会**退出，所以必须显式 disconnect

## 2. `disconnect()` 资源释放

业务方何时该调 `disconnect()`：

| 场景 | 调不调 | 原因 |
| --- | --- | --- |
| Laravel Octane 长进程 | ✅ 必调 | 避免 fd 泄漏 |
| PHP-FPM 短进程（每请求新进程） | ❌ 不调 | 进程结束自动释放 |
| `kafka:work` worker | ❌ 不调 | 退出前 `WorkCommand` 内部 `$consumer->close()` + `$producerFactory->flushAll()` |
| `kafka:dlq:tail` | ❌ 不调 | 退出前 `DlqTailCommand` 内部 `$consumer->close()` |
| 单元测试中切换 connection | ✅ 调 | 强制重建单例 |

### API

```php
$manager = app('kafka.manager');

// 释放指定 connection
$manager->disconnect('default');
$manager->disconnect('reports');

// 释放所有 connection
$manager->disconnect();  // null = 默认
foreach (array_keys(config('kafka.connections')) as $name) {
    $manager->disconnect($name);
}
```

### 释放后行为

- `connections[$name]` 被 unset
- `configs[$name]` 也被 unset（连带失效）
- 下次 `connection($name)` 重新走懒加载路径

## 3. 长进程内存管理

`kafka:work` 长驻进程跑久了会有内存碎片、librdkafka 内部 buffer 累积。建议：

### 用 `--max-time` 定期重启

```bash
php artisan kafka:work --max-time=3600
# 跑满 1 小时后自动退出，supervisor 拉起新进程
```

### 用 `--max-jobs` 限制处理数

```bash
php artisan kafka:work --max-jobs=10000
# 处理 10000 条任务后退出
```

### 监控 worker 内存

```bash
# Linux 看 RSS
ps -o pid,rss,cmd -C php | grep kafka:work

# 用 supervisor 自动重启
[program:laravel-kafka-work]
autorestart=true
startretries=3
```

## 4. Producer 复用

`ProducerFactory` 单例缓存（按 `config name`）：

```php
$factory = app(ProducerFactory::class);
$producer1 = $factory->make($config);
$producer2 = $factory->make($config);
// $producer1 === $producer2（同一 librdkafka 实例）
```

**不要**自己 `new Producer($kafka)` —— 绕过单例缓存，会创建多个 librdkafka 实例浪费资源。

### 多 connection 共享 producer？

默认**不**共享（每个 connection 自己的 producer）。业务方有特殊需求可定制：

```php
class SharedProducerFactory
{
    private array $producers = [];

    public function make(KafkaConfig $config): Producer
    {
        $key = $config->brokers() . '|' . $config->protocol();
        if (! isset($this->producers[$key])) {
            $this->producers[$key] = Producer::fromConf($this->buildConf($config));
        }
        return $this->producers[$key];
    }
}
```

> 大多数场景用默认按 `config name` 缓存已足够。

## 5. KafkaConfig 不可变

`KafkaConfig` 构造后**不能改**。业务方要"换配置"必须重建：

```php
$config1 = Kafka::config('default');

// 改 brokers 重新构造
$config2 = new KafkaConfig(
    name: 'default',  // 名字相同，复用 producer 单例
    brokers: 'new-broker:9092',
    // ... 其他字段从 $config1 拷贝
);

// ❌ 错：$config1 不提供 setter
// $config1->setBrokers('new-broker:9092');
```

> 大多数业务方场景**不需要**改 config（启动时 config 一次到位）。需要动态切 broker 时，重建 `KafkaConfig` 实例。

## 6. 常见错误排查

### 6.1 `Kafka produce timeout after 5000 ms`

**症状**：`Producer::send()` 抛 `KafkaException`，消息未落 broker。

**排查步骤**：

1. `KAFKA_BROKERS` 配置对吗？
   ```bash
   kcat -b $KAFKA_BROKERS -L  # 列出所有 topic（验证连通）
   ```

2. broker 慢 / 满？
   ```bash
   # 看 broker 磁盘
   df -h /var/lib/kafka
   # 看 broker 进程
   ps aux | grep kafka
   ```

3. `acks=all` 但 `min.insync.replicas` > 实际副本数？
   ```bash
   kafka-run-class.sh kafka.tools.GetOffsetShell --broker-list $BROKER --topic test
   # 看 topic 副本数
   ```

4. librdkafka 内部 log 启用 debug：
   ```php
   'producer' => ['debug' => 'broker,topic,msg', ...],
   ```

### 6.2 `Connection refused`

**症状**：worker 启动后立刻报 "Connection refused"。

**排查**：

1. broker 是否启动？
   ```bash
   docker ps  # 看 kafka 容器
   ```
2. 端口对吗？（PLAINTEXT 默认 9092）
   ```bash
   nc -zv localhost 9092
   ```
3. broker advertised listener 配置对吗？（容器外访问用 `localhost:9092`，容器内用 `kafka:9092`）

### 6.3 `SerializationException: Failed to decode`

**症状**：消费端解码消息失败。

**排查**：

1. producer 用的 serializer 和 consumer 匹配吗？
   ```php
   // 消费端
   $message->header('x-serializer');  // 'php' / 'json' / 'avro'
   ```
2. payload 是否被截断？（broker 端 `message.max.bytes`）
3. 业务方自定义 serializer 抛错？看 `error_log` 找原始异常

### 6.4 `Kafka consume error` 错误码排查

**症状**：`Consumer::poll` 抛 `KafkaException`（librdkafka 内部错误），错误码带 `__` 前缀。

**code 含义**（v0.5.2 修正，已对照官方 `rdkafka.h`）：

| 码 | 常量 | 含义 |
| --- | --- | --- |
| `-185` | `RD_KAFKA_RESP_ERR__TIMED_OUT` | 正常超时，`WorkCommand` 内部处理 |
| `-195` | `RD_KAFKA_RESP_ERR__TRANSPORT` | broker 连接断 |
| `-186` | `RD_KAFKA_RESP_ERR__INVALID_ARG` | 配置错 |
| `-188` | `RD_KAFKA_RESP_ERR__UNKNOWN_TOPIC` | 本地未知 topic |
| `3` | `RD_KAFKA_RESP_ERR_UNKNOWN_TOPIC_OR_PART` | broker 协议码：topic/partition 不存在（**无 `__` 前缀**） |
| `6` | `RD_KAFKA_RESP_ERR_NOT_LEADER_FOR_PARTITION` | broker 协议码：非分区 leader（rebalance 期间常见） |
| `12` | `RD_KAFKA_RESP_ERR_OFFSET_METADATA_TOO_LARGE` | broker 协议码：offset 元数据过大 |

> **注意**：`__` 前缀的**内部错误码是负数**（如 `__TIMED_OUT = -185`），broker **协议错误码是正数**（如 `NOT_LEADER_FOR_PARTITION = 6`）。排查时先区分两类。

**排查**：

```bash
# librdkafka 错误码 → 错误名
# https://github.com/confluentinc/librdkafka/blob/master/src/rdkafka.h
php -r "echo rd_kafka_err2str(-185) . PHP_EOL; echo rd_kafka_err2str(6) . PHP_EOL;"
```

### 6.5 worker 启动后立即死循环空转

**症状**：`--sleep=0` + 无消息时 CPU 100%。

**解决**：

```bash
# 设合理的 sleep
php artisan kafka:work --sleep=2
```

### 6.6 消息积压但 worker 不消费

**症状**：topic 消息累积，`kafka:work` 不读。

**排查**：

1. 同一 group 有几个 worker？
   ```bash
   # Kafka Manager
   kcat -b $BROKER -L -t your-topic
   ```
2. 同一个 `KAFKA_GROUP_ID` 多个 worker → 自动 partition 互斥
3. `enable.auto.commit=false`（必须）+ 业务 `Job::delete()` 调 `commit` 链
4. 看 `KAFKA_AUTO_OFFSET_RESET=error` 但没历史 offset → 报错

### 6.7 `kafka:work` 内存增长

**症状**：跑 1 周后 RSS 涨到 1GB+。

**解决**：

```bash
# 1. 加 --max-time 定期重启
php artisan kafka:work --max-time=3600

# 2. supervisor 自动重启
autorestart=true
startsecs=10
```

### 6.8 PHP 8.2+ 动态属性弃用

**症状**：PHP 8.2+ 报 `Deprecated: Creation of dynamic property`。

**解决**：

```php
class KafkaConfig
{
    private string $brokers;  // 显式声明
    // ...
}
```

> v0.5 计划：把 `src/Config/KafkaConfig.php` 12 个 dynamic property 改成 explicit declaration。

## 7. 生产部署清单

### 部署前

- [ ] `ext-rdkafka` 装好（`php -m | grep rdkafka`）
- [ ] `librdkafka` 版本 ≥ 1.5（`librdkafka --version` 或 `pkg-config --modversion rdkafka`）
- [ ] composer install 成功（`composer install --no-dev`）
- [ ] `php artisan vendor:publish --tag=kafka-config` 跑过
- [ ] `KAFKA_BROKERS` / `KAFKA_GROUP_ID` 等环境变量配好
- [ ] broker `advertised.listeners` 配置正确（业务方能访问）
- [ ] `KAFKA_FAILED_DRIVER` 选好（`hybrid` 推荐）

### 部署后

- [ ] `php artisan kafka:work` 能启动
- [ ] `kafka:work` 能拉消息（用 `kcat` 写一条测试消息）
- [ ] `php artisan queue:failed` 能用（hybrid 模式）
- [ ] `php artisan kafka:dlq:tail <topic>` 能用（dlq 模式）
- [ ] supervisor / systemd 配置正确（`stopwaitsecs=30`，自动重启）
- [ ] worker 数量 = partition 数量（避免浪费）
- [ ] DLQ retention 配好（`KAFKA_DLQ_RETENTION_MS`）
- [ ] Horizon 配置（如启用 metrics）

### 监控

- [ ] Kafka broker：`kafka_exporter` + Prometheus
- [ ] Laravel app：`horizon_metrics` + 自定义事件
- [ ] 告警：DLQ 写入速率突增、worker 长时间不消费

## 8. 性能基准

v0.3 提供的 `benchmarks/` 脚本模板：

```bash
# benchmarks/produce-throughput.php
php benchmarks/produce-throughput.php
# 期望：单 partition 单 producer 极限 ~10k msg/s
```

```bash
# benchmarks/consume-throughput.php
php benchmarks/consume-throughput.php
# 期望：单 consumer 极限 ~10k msg/s
```

### 影响吞吐的关键参数

| 参数 | 调大效果 |
| --- | --- |
| `producer.batch_size` | ↑ batch 越大吞吐越高（默认 10000 字节） |
| `producer.linger_ms` | ↑ 等更久攒 batch（默认 5ms） |
| `producer.compression` | `snappy` / `zstd` 压缩比高（CPU 换带宽） |
| `consumer.fetch_min_bytes` | ↑ 拉更少但更大（默认 1 字节） |
| `consumer.fetch_max_bytes` | ↑ 单次 fetch 上限（默认 50MB） |

### 实测基线

业务方在 1 个 producer + 1 个 consumer + 3 个 partition + snappy 压缩下：

- **produce**：~8-12k msg/s（1KB payload）
- **consume**：~6-10k msg/s（1KB payload）
- **E2E 延迟**：p50 ~ 50ms，p99 ~ 500ms

> 实际数字取决于 broker 网络、磁盘、partition 数量。

## 9. 已知限制（v0.5.2）

| 限制 | 影响 | 临时方案 |
| --- | --- | --- |
| `kafka:delay:work` 未发布 | 时间轮延迟消息需业务方自己起 worker | 手动起 tier topic listener（见 [06-延迟消息 §6](06-延迟消息.md#6-当前-v041-临时方案)） |
| `kafka:replay` 不实际 reproduce | 无法直接重放 | 用 `kcat` + Python 脚本（[08 §4](08-回溯Replay.md#4-用-kcat-做完整重放临时方案)） |
| `kafka:dlq:tail` 输出 payload 截断 200 字节 | DLQ 排障看不到完整 payload | 用 `kcat` 查单条 |
| `kafka.handlers` per-topic 路由未实现 | 自定义 handler 需扩展 `HandlerResolver` | 见 [04-Consumer §4](04-Consumer-消费消息.md#4-自定义-handlerv01-占位v03-增强) |

> **已修复（不再列）**：`KafkaConfig` dynamic property（v0.4.8 已改显式声明）、
> `Header::SERIALIZER` 硬编码（v0.5.0/0.5.1 已配置化）、`kafka:horizon:snapshot` 模板化
> （v0.4.4 已真实现）、`KafkaQueue::size/pop` 占位（v0.4.5/0.4.6 已真实现）。
