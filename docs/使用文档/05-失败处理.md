# 05 失败处理

`laravel-kafka` 提供三种失败处理模式 + 两个高级工具，覆盖从简单到复杂的失败场景。

---

## 1. 三种模式对比

| 模式 | 配置 | 失败后行为 | 适用 |
| --- | --- | --- | --- |
| `database` | `KAFKA_FAILED_DRIVER=database` | 写 Laravel `failed_jobs` 表，`queue:failed` / `queue:retry` | 团队习惯 Laravel 原生排障 |
| `dlq` | `KAFKA_FAILED_DRIVER=dlq` | 写独立 DLQ topic（默认 `<topic>.dlq`） | 多语言消费 DLQ / 大量失败需离线分析 |
| `hybrid` | `KAFKA_FAILED_DRIVER=hybrid` | 重试入库 + 超限 DLQ | **生产推荐**（兼具明细查询 + 离线分析） |

---

## 2. `database` 模式

```dotenv
KAFKA_FAILED_DRIVER=database
KAFKA_FAILED_TABLE=failed_jobs
KAFKA_FAILED_DB_CONNECTION=
```

`KAFKA_FAILED_DB_CONNECTION` 为空时用 Laravel 默认 DB connection。

### 业务流程

1. Job 抛异常 → `KafkaJob::fail()` 调 `DatabaseFailedJobHandler::log()`
2. 写一行到 `failed_jobs` 表（含 payload、exception、trace、UUID）
3. worker 打印 `<error>DLQ</error>` 日志
4. **不**自动重试，需业务方手动 `queue:retry <uuid>`

### Laravel 命令兼容

```bash
php artisan queue:failed                # 列出所有失败
php artisan queue:retry <uuid>          # 重试单条
php artisan queue:retry --all          # 重试全部
php artisan queue:forget <uuid>        # 删除单条
php artisan queue:flush                 # 清空表
```

> 这些命令在 `database` / `hybrid` 模式下都可用。`dlq` 模式不写 `failed_jobs` 表，命令返回空。

---

## 3. `dlq` 模式

```dotenv
KAFKA_FAILED_DRIVER=dlq
KAFKA_DLQ_TOPIC=                       # 空 = 自动 <default>.dlq
KAFKA_DLQ_AUTO_SUFFIX=.dlq             # 自定义后缀
KAFKA_DLQ_RETENTION_MS=1209600000      # 14 天
```

### 业务流程

1. Job 抛异常 → `DlqFailedJobHandler::handle()` produce 一条消息到 DLQ topic
2. 原始消息体 + 异常 class / message / trace 写入 Kafka headers
3. worker 打印 `<error>DLQ</error>` 日志
4. **不**写 `failed_jobs` 表

### DLQ 消息格式

```php
[
    'payload'   => '<原始 payload 字符串>',
    'headers'   => [
        'x-failed-at'         => '1700000000123',         // ms 时间戳
        'x-exception-class'    => 'App\\Exception\\...',   // FQN
        'x-exception-message' => 'User not found',        // 截断
        'x-exception-trace'    => '#0 /path/to/...',       // 截断到 trace_truncate_bytes
        'x-original-topic'     => 'laravel-jobs',
        'x-original-partition' => '0',
        'x-original-offset'    => '12345',
        'x-attempts'           => '3',
        'x-queue'              => 'laravel-jobs',
        'x-connection'         => 'default',
    ],
    'key'       => '<原 key>',
]
```

### 消费 DLQ

```bash
php artisan kafka:dlq:tail laravel-jobs.dlq --max=100
```

详见 [07-DLQ运维](07-DLQ运维.md)。

## 4. `hybrid` 模式（**生产推荐**）

```dotenv
KAFKA_FAILED_DRIVER=hybrid
KAFKA_MAX_ATTEMPTS=3
KAFKA_TRACE_TRUNCATE=32768
KAFKA_MESSAGE_TRUNCATE=4096
```

`config/kafka.php` 配置 `fatal_exceptions`（**立即**进 DLQ 的异常类列表）：

```php
'hybrid' => [
    'fatal_exceptions' => [
        \LaravelKafka\Exceptions\SerializationException::class,
        \Illuminate\Validation\ValidationException::class,
        \App\Exceptions\BizFatalException::class,  // 业务方自定义
    ],
    'max_attempts'           => 3,
    'trace_truncate_bytes'   => 32768,
    'message_truncate_bytes' => 4096,
],
```

### 业务流程

```
Job 抛异常
    │
    ├─ 异常是 fatal_exceptions 之一？
    │   └─ 是 → 双写 database + DLQ，attempt 不增加
    │
    └─ 否则：
        │
        ├─ attempt < max_attempts ?
        │   └─ 是 → requeue 回主 topic（attempt + 1）
        │
        └─ 否 → 双写 database + DLQ
```

`attempt` 由 `x-attempt` header 跟踪，每次 requeue +1。

### retry header 生命周期

```
首次入队
  x-attempt: 0
    ↓ 失败
requeue（第 1 次）
  x-attempt: 1
    ↓ 失败
requeue（第 2 次）
  x-attempt: 2
    ↓ 失败
达到 max_attempts=3
  ↓
双写 failed_jobs + DLQ
  x-attempt: 2 (未增加, 标记终结)
```

## 5. 异常类路由 `ExceptionClassRouter`（v0.3）

不同异常类分发到不同 DLQ topic，便于差异化处理：

```php
'connections' => [
    'default' => [
        'failed' => [
            'driver' => 'dlq',  // 或 hybrid
            'dlq' => [
                'topic' => 'laravel-jobs.dlq.default',
                'topic_map' => [
                    'App\\Exception\\BizFatalException'       => 'laravel-jobs.dlq.fatal',
                    'App\\Exception\\NetworkTimeoutException' => 'laravel-jobs.dlq.transient',
                    'InvalidArgumentException'                => 'laravel-jobs.dlq.validation',
                ],
            ],
        ],
    ],
],
```

### 匹配规则

- 遍历 `topic_map`
- 第一个 `$exception instanceof $class` 命中的 key 对应 topic
- 找不到匹配 → 兜底 `topic`（`laravel-jobs.dlq.default`）

### 适用场景

- `BizFatalException` → `fatal` topic（人工处理 + 告警）
- `NetworkTimeoutException` → `transient` topic（自动重试 + 监控网络）
- `InvalidArgumentException` → `validation` topic（开发期排查参数问题）
- 其他 → `default` topic（常规失败）

### 业务方自定义路由

```php
// 在 app/Providers/AppServiceProvider.php
use LaravelKafka\Queue\Failed\ExceptionClassRouter;
use LaravelKafka\Queue\Failed\FailedJobHandlerInterface;

$this->app->extend(FailedJobHandlerInterface::class, function ($handler, $app) {
    $config = $app['kafka.manager']->config();
    $dlqConfig = $config->failed()['dlq'] ?? [];

    $router = new ExceptionClassRouter(
        $dlqConfig['topic_map'] ?? [],
        $dlqConfig['topic'] ?? ($config->defaultTopic() . '.dlq'),
    );

    // 用 $router 包装 $handler
    return new \App\Kafka\Handlers\CustomDlqHandler($handler, $router);
});
```

## 6. DLQ 限速 `DlqRateLimiter`（v0.3）

业务故障爆炸时（100k 条失败消息/分钟）会撑爆 DLQ topic。限速器按"每分钟 N 条"控制：

```php
$limiter = new \LaravelKafka\Queue\Failed\DlqRateLimiter(100);  // 每分钟 100 条

if ($limiter->allow()) {
    // 写 DLQ
} else {
    // 超限：丢弃 / 累加 batch 计数 / 报警
    \Log::warning('DLQ rate limit exceeded, dropped message', [
        'current' => $limiter->currentCount(),
        'max'     => $limiter->maxPerMinute(),
    ]);
}
```

### 行为

- 滑动窗口（每 60s 重置计数器）
- 返回 `true` = 允许写入，`false` = 已超限
- 业务方决定"丢弃"或"累加 batch"

### 当前实现限制

**单进程内存计数器**。多 worker 部署会**各自限速**（实际是 100 × N 条/分钟）。生产环境推荐用 Redis 共享计数器（v0.5 评估）。

### 接入

`DlqFailedJobHandler` 在构造时接受可选 `$rateLimiter`：

```php
// 在 app/Providers/AppServiceProvider.php
use LaravelKafka\Queue\Failed\DlqFailedJobHandler;
use LaravelKafka\Queue\Failed\DlqRateLimiter;
use LaravelKafka\Producer\Producer;

$this->app->extend(DlqFailedJobHandler::class, function ($handler, $app) {
    return new DlqFailedJobHandler(
        producer: $app->make(\LaravelKafka\Producer\Producer::class),
        topic: 'laravel-jobs.dlq',
        config: ['rate_limit_per_minute' => 100],  // 业务方自定义
        rateLimiter: new DlqRateLimiter(100),
    );
});
```

## 7. 完整示例：业务方的混合配置

```php
// config/kafka.php
'connections' => [
    'default' => [
        'brokers' => env('KAFKA_BROKERS', 'localhost:9092'),
        'queue'   => 'laravel-jobs',
        'failed' => [
            'driver' => 'hybrid',
            'database' => [
                'table'      => 'failed_jobs',
                'connection' => null,  // 用默认 DB
            ],
            'dlq' => [
                'topic' => 'laravel-jobs.dlq.default',
                'topic_map' => [
                    'App\\Exception\\BizFatalException' => 'laravel-jobs.dlq.fatal',
                ],
                'auto_topic_suffix' => '.dlq',
                'retention_ms'      => 1209600000,
            ],
            'hybrid' => [
                'fatal_exceptions' => [
                    \LaravelKafka\Exceptions\SerializationException::class,
                    \App\Exceptions\BizFatalException::class,
                ],
                'max_attempts' => 3,
            ],
        ],
    ],
],
```

行为：

- 序列化错误或业务致命异常 → 立即双写 database + DLQ
- 其他异常 → 重试 3 次（每次 `x-attempt + 1`）→ 仍失败则双写
- 业务方 `php artisan queue:failed` 查所有失败（含临时）
- 业务方 `php artisan kafka:dlq:tail laravel-jobs.dlq.fatal` 查致命失败

## 8. 失败处理 + 事件订阅

`LaravelKafkaServiceProvider` 监听 `Illuminate\Queue\Events\JobFailed`，业务方可订阅：

```php
// app/Providers/EventServiceProvider.php
protected $listen = [
    \Illuminate\Queue\Events\JobFailed::class => [
        \App\Listeners\NotifyOpsOnFailure::class,
    ],
];
```
