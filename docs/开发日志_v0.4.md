## v0.4 唯一任务: Horizon 兼容（2026-08-25）

### 目的

业务方常用 Laravel Horizon 管理队列（dashboard / 监控 / supervisor）。Horizon 强依赖 Redis metrics：worker 处理完任务后写 `<prefix>queue:<name>` Hash（throughput / runtime），Horizon UI 读这些 key 展示。

**v0.4 目标**：让 `kafka:work` 处理消息后，写与 Horizon 5.x **完全一致**的 Redis key 格式，业务方**零修改**地看到 Kafka 队列出现在 Horizon dashboard。

### Horizon 5.x Redis key 规范（[参考][1]）

| Key | 类型 | 内容 |
| --- | --- | --- |
| `<prefix>measured_queues` | Set | queue 名列表（带 `queue:` 前缀） |
| `<prefix>queue:<queueName>` | Hash | `{throughput: int, runtime: float}` |
| `<prefix>measured_jobs` | Set | job 类名列表（带 `job:` 前缀） |
| `<prefix>job:<className>` | Hash | `{throughput: int, runtime: float}` |
| `<prefix>snapshot:queue:<queueName>` | Sorted Set | 历史快照（score = timestamp） |
| `<prefix>snapshot:job:<className>` | Sorted Set | 同上 |
| `<prefix>last_snapshot_at` | String | 最后 snapshot timestamp |

`<prefix>` 默认 `horizon:`（业务方在 `config/horizon.php` 改 → 我们的 `--horizon-prefix` 同步）。

[1]: https://github.com/laravel/horizon/blob/master/src/Repositories/RedisMetricsRepository.php

### Horizon 5.x `updateMetrics` Lua 脚本（逐字复制）

```lua
redis.call('hsetnx', KEYS[1], 'throughput', 0)
redis.call('sadd', KEYS[2], KEYS[1])
local hash = redis.call('hmget', KEYS[1], 'throughput', 'runtime')
local throughput = hash[1] + 1
local runtime = 0
if hash[2] then
    runtime = ((hash[1] * tonumber(hash[2])) + tonumber(ARGV[1])) / throughput
else
    runtime = tonumber(ARGV[1])
end
redis.call('hmset', KEYS[1], 'throughput', throughput, 'runtime', runtime)
```

**关键**：throughput 是**累计计数**（永久 +1），runtime 是**加权平均**（平滑收敛）。

### 关键设计点

#### 1. `HorizonMetricsRecorder` 的最小依赖

- **不**强依赖 `illuminate/redis`（避免给纯 Kafka 项目加 Redis 依赖）
- 类型 hint 用 `mixed`（PHP 7.4 兼容，运行时 Duck typing）
- 业务方装 Horizon / illuminate-redis 后才用 `--horizon-metrics`
- 不装 → 容器 `bound('redis')` 失败 → `WorkCommand` 警告 + 跳过

#### 2. `NativeHandler` 的容器守卫

```php
private function recordHorizonMetrics(Message $message, float $startMs, bool $success): void
{
    if (! $this->container->bound(HorizonMetricsRecorder::class)) {
        return;  // 业务方没启 horizon metrics → 静默跳过
    }
    try {
        $recorder = $this->container->make(HorizonMetricsRecorder::class);
        $runtimeMs = (microtime(true) * 1000) - $startMs;
        $topic = (string) ($message->header(Header::ORIGINAL_TOPIC) ?? 'laravel-jobs');
        $recorder->incrementQueue($topic, $runtimeMs);
    } catch (\Throwable $e) {
        error_log('[laravel-kafka] Horizon metrics record failed: ' . $e->getMessage());
        // 静默：metrics 失败不应影响业务处理
    }
}
```

- 成功**和**失败都记录（保持与 Horizon 5.x 一致：throughput 是"尝试处理数"）
- 任何异常 → error_log + 继续（**不**影响业务）

#### 3. 业务方用法

```bash
# 1. 装 Horizon
composer require laravel/horizon
php artisan horizon:install
# （在 config/database.php 配 redis connection "horizon"）

# 2. 跑 kafka worker（带 Horizon metrics）
php artisan kafka:work --horizon-metrics --horizon-prefix=horizon: --horizon-redis=horizon

# 3. 打开 /horizon → dashboard 看到 Kafka 队列
```

或自定义 prefix（如多租户隔离）：
```bash
php artisan kafka:work --horizon-metrics --horizon-prefix=tenant1:
```

#### 4. PHP 8.0+ 兼容细节

- `str_replace(',', '.', $runtimeMs)` —— Lua 不接受 ',' 作为小数点
- 业务方传 `12.5`（float）→ 直接转字符串
- 业务方传 `12,5`（用 ',' 当小数点，欧洲风格）→ 替换为 `'12.5'`

### 已知待办（v0.4.1+）

- **`kafka:horizon:snapshot` 命令**：当前只 print 参数（业务方应同时启用 Horizon 原生 `horizon:snapshot`）—— v0.4 简化
- **job class metrics**：当前 NativeHandler 只调 `incrementQueue`，没调 `incrementJob`（业务方需要把 job 解析后传 class 名）—— v0.4.1
- **throughput 衰减**：Horizon 原生 `snapshot()` 把当前 metrics 清 0（下次 increment 重新累计）；v0.4 metrics 永久累加 → Horizon dashboard 的"per minute" 数字会偏大
- **SnapshotRedis connection**：业务方在 testbench 跑测试时没真 Redis → `bind('redis')` 失败 → 警告 + 跳过
